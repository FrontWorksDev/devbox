# dev CLI 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** シェル版 `dev` を、標準ライブラリだけの Go 単一バイナリで置き換える。プロジェクトのコードを隔離コンテナで動かすための CLI。

**Architecture:**
- 純粋な部分（設定の解析、パスと名前の計算、docker の引数組み立て、op の argv）は小さな `internal/*` パッケージに分ける。
- 外部とのやりとり（docker / git の実行、`syscall.Exec`、tty、環境変数）は `app.Deps` に集め、テストでは偽物に差し替える。
- `image/` は `//go:embed` で埋め込み、`dev build` で書き出す。

**Tech Stack:** Go 1.27.4（asdf、`.tool-versions`）、標準ライブラリのみ、`CGO_ENABLED=0`、docker CLI。

**Spec:** `docs/superpowers/specs/2026-11-19-dev-cli-design.md`（以下「設計書」。章番号は設計書のもの）

## Global Constraints

- 外部モジュール禁止（`go.mod` に `require` が出てはいけない）。cgo 禁止。
- `go.mod`: `module devbox` / `go 1.27`。
- ユーザー向けメッセージは日本語、`dev: ` で始めて標準エラーへ。エラー時は終了コード 1。
- シークレットの値を argv・ログ・エラーメッセージに載せない。docker には `-e NAME` だけ渡す。
- コメントは日本語で「なぜ」を書く。特にセキュリティ上の理由。
- コミットは**ユーザーに確認してから**（CLAUDE.md）。各タスク末尾の「コミット」は提案のタイミングを示す。
- `op` コマンドは実行しない。`~/.ssh`、`~/.aws`、`~/.config/op`、`.env` の値を読まない。
- 実機検証では `devbox:dev-test` と一時フォルダだけを使う。`devbox-*` の資源と `devbox:latest` は消さない。

## Review Focus

1. **docker が PATH にない** → `dev: docker が見つかりません` で終了 1。Go のスタックトレースや英語のエラーを出さない（Task 8 にテスト）。
2. **`.devbox` が CRLF 改行・タブ区切り・末尾改行なし** → 普通に解析できる（Task 2 にテスト）。
3. **`port 0` や `port 70000`** → 正規表現は通るが、docker で分かりにくく失敗する。1〜65535 の範囲外は行番号付きでエラーにする（Task 2 にテスト。builder の判断として設計書の決定事項に追記する）。
4. **git の出力の末尾改行、git がない、git リポジトリではない** → 改行を除く。失敗したらカレントディレクトリにフォールバックする（Task 3 にテスト）。
5. **ホストの環境変数が空文字で設定されている（`FOO=`）** → 「設定されている」とみなして渡す。`LookupEnv` で判定する（Task 9 にテスト）。

### Task 6: approval（.devbox の承認）
